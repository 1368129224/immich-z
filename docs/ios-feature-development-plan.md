# iOS 功能开发与验收计划

> 状态：需求已逐模块核对；实现方案待逐项验证。基于当前仓库源码和本次产品决策编写，不引用此前设计文档。目标仅为原生 iOS。
> 范围说明：本文中“已实现”仅表示源码中存在相应路径，不代表经过真机或端到端验收。“目标”不代表现有能力。首次公开免费版须完成**本次已确认清单**，并非声称覆盖 Immich 全部移动端功能。

## 1. 产品目标与交付约束

- 面向使用自托管 Immich 的 iPhone 用户，提供接近 iOS「照片」的网格、查看器和手势，并保持本机/服务器资产身份、操作和备份状态真实可信。
- 开发顺序选择**页面先全覆盖**，再集中完善细节与质量；但账号隔离、资产身份与删除安全是每个页面实施的前提，不能留到收尾。
- 开发/内部测试版本可展示“开发中／仅可查看”的集合入口；**公开首发不得残留未完成的已承诺入口**。首发后仍可扩展未纳入本清单的功能。
- 不在照片页或查看器放手动上传按钮；备份是用户明确开启后执行的自动后台能力。
- 收费、订阅、品牌/许可和正式商店发布属于独立发布专项；不将未解决的发布问题误写为已具备上架条件。

## 2. 跨页面数据与安全合同（先建立，持续复用）

### 2.1 身份与资产状态

- 身份键必须包含服务器规范化地址与服务器用户 ID；本机资产使用 PhotoKit `localIdentifier`，关联关系以**账户 + 本机 ID + 经验证的服务器资产 ID**存储。来源筛选依据**副本是否存在**，不是依据当前是否已载入 DTO。
- 同一逻辑资产在“全部”只出现一次；在“本机”和“云端”均可出现（若两端均有）；相册/搜索筛选仍需满足该来源的真实成员/查询条件。
- 状态至少区分：仅本机、仅云端、双端已确认、已知匹配但服务器元数据待载、待核验、核验失败/未知、待上传、上传中、等待网络/原件、上传失败。未知、核验失败不可显示为“未上传”，传输完但服务器未确认不可显示“已备份”。
- 网格仅对需关注的状态常显角标；成功匹配的完整信息可在详情/备份面板查看。`NativeGridItem` 的身份在本机/云端/合并过渡时要保持可追踪，防止选择和查看器焦点丢失。
- 所有页面共享同一资产模型、能力判断和操作结果流；收藏、删除、匹配或上传变更后，所有已打开页面一致更新。服务器匹配已知但对象尚未加载时按 ID 请求/验证后才能执行服务器侧操作。
- 匹配缓存和原件指纹持久化，**普通刷新不清空**。按账户隔离并处理删除、权限撤销、PhotoKit ID 失效及服务器资产失效；主动仅删云端后立即使旧关联失效。

### 2.2 操作合同

- 每项操作先计算选择集内适用/跳过数量与原因，必要时让用户确定来源，再执行；完成后报告成功、失败与部分成功。绝不静默把本机操作变成服务器操作，或反过来。
- 删除本机、服务器或两端每次明确范围；双端照片不设置危险默认值。自动备份开启且本机仍在已选相册时，“仅删云端”应**事前**告知后续可能自动重传（用户明确选择此行为）。不因删除相册成员关系而删除原件。
- 本机操作遵循 PhotoKit 权限及系统确认；若启用 iCloud Photos，本机删除可能传播到其他设备，危险操作需提示。不能承诺系统照片“最近删除”的管理能力。
- 共用加载、无数据、离线、权限不足、服务器能力不可用、部分成功等状态组件和 VoiceOver 描述；私有缓存/请求按账户隔离。

## 3. 照片页面

### 3.1 信息架构与交互

- 来源切换：**全部／本机／云端**；双端资产在两个来源筛选中都出现，在“全部”去重。拒绝 PhotoKit 权限仍可看云端。
- 按拍摄日期分组，升序布局、最新在底部；首期不做年/月/日多级视图。首次进入定位最新；手动刷新、回前台、分页、匹配状态更新保持当前可见资产与相对位置；新照片出现时非侵入提示，仅用户主动跳转才回最新。切换来源筛选时先尽量保持同一资产，若该资产不属于新筛选则定位临近日期并提示。
- 边到边网格，双指**连续缩放并保持焦点**；结束可吸附舒适档位。照片/视频缩略图按可见范围优先加载，离屏取消。视频标记与状态角标避免重叠。
- 常驻“选择”按钮，同时长按进入与拖动选取，支持全选/取消；工具栏目标：分享、收藏、归档、加入相册、保存到本机、删除。**没有上传按钮**。针对混选预览适用/跳过项及结果。
- 本机独有收藏通过 PhotoKit；归档仅作用于已有服务器副本；加入相册必须选择本机或服务器目标，不隐式上传。保存云端原件到系统照片，已有本机副本时仍允许用户主动重复保存，操作前提示可能重复。

### 3.2 实施与验收

1. 提取统一资产身份、来源查询与状态投影，修正仅凭当前页面 DTO 判断“仅本机”的问题。
2. 将 `loadInitial()` 的重置式刷新与回前台无条件滚到底改成增量更新/稳定可见锚点；分页失败按页重试，不丢已有数据。
3. 把整数列跳变式捏合替换为手势期连续尺寸与焦点锚定；通过真机校准范围及帧率。
4. 在多选操作层实现来源适用性检查、确认、部分失败反馈；多选和查看器使用相同操作服务。
5. 用有重复资产、部分载入、跨时区、弱网、大图库、有限权限及快速切换筛选的样本验收无重项、无错标、无异常跳屏。

## 4. 照片查看器与详情页

- 简洁工具栏：顶部返回/日期，底部分享、收藏、详情、“更多”；删除与归档置于“更多”。单击画面切换沉浸模式，关闭后返回原网格位置。
- 原尺寸横滑切换、下滑关闭；放大后优先图片平移，禁止误切换/关闭，恢复原尺寸后才重新允许。保留双击与捏合缩放，明确视频、Live Photo 和图片的手势冲突优先级。
- 本机独有照片通过 PhotoKit 收藏；双端资产收藏同步更新两端，分别显示成功/失败，不误报“全部成功”。删除每次明确作用范围，不提供手动上传。
- 分享优先真实原文件及可保留的元数据，准备时有进度与取消；取不到原件时询问是否用预览，不静默降质。远端视频、Live Photo、iCloud 原件分别验收，不把认证 URL 当成未经准备的可分享文件。
- 详情首期：时间、地点、文件名、尺寸、格式、大小、来源、本机/云端副本状态；可得 EXIF 为次级区域，缺失不猜测、不误报“未上传”。
- 原图/视频加载错误按离线、权限、iCloud 原件未就绪、服务器错误、格式不支持等分类并可原位重试；视频打开自动播放、不循环、切页立即暂停、音量遵循系统。远端认证播放及请求取消需做真机验证。

## 5. 相册页面

- 混合卡片列表，可筛选全部／本机／云端，默认名称排序，明确显示来源。仅在同名归一后两侧**各唯一一个**时自动组合；同侧重名保持独立。组合仅展示，不同步成员或隐式操作另一侧。
- 卡片分别显示两侧数量；去重总数仅在完整成员与匹配关系可信时展示，否则注明“已加载 N 项”，不得拿已分页加载项冒充全部。
- 详情只显示所属两侧相册的**真实成员**，默认合并去重，可筛选来源；日期方向、焦点缩放、位置保持、多选与照片页一致。
- 加入本机相册只针对已有本机副本；加入服务器相册只针对已有服务器副本，不隐式上传。移除成员必须明确来源，**不删除原件**。首期支持两侧能力范围内的重命名和封面管理；本机自定义封面若 PhotoKit 不支持，不提供伪功能；描述与协作者不在本期。
- 相册删除保留两种清晰分开的模式：①仅删容器，保留原件；②删除相册及该侧成员的**照片原件**。组合卡每次先选一侧，绝不默认两端操作。模式②先预览实际原件数量/来源、说明其他相册中的同一原件也会受影响、提示本机 iCloud 同步风险，再次明确确认；分项报告成功/失败。服务器回收站语义以实际 API 验证，不能宣称一律不可恢复。

## 6. 搜索页面

- 首页：服务端探索分类 + **仅本设备保存**的最近搜索；提供清除入口。单搜索框，短暂停顿自动搜索，键盘提交立即搜索；关键词/筛选变更时取消或丢弃旧请求，避免晚返回覆盖新结果。
- 云端文件/描述搜索与智能语义搜索自动并行/融合；智能能力不存在或失败时普通搜索与本机搜索继续，告知结果不完整。用户无须切换模式。
- 本机未上传资产首期仅用可取得的文件名与基础信息（日期、类型、收藏、本机相册）做有限搜索；无本机人脸、OCR、语义承诺；有限权限仅查询已授权资产。
- 筛选：照片/视频、日期范围、全部/本机/云端、收藏、相册。相册筛选严格按各侧真实成员，不因双端匹配而隐式把照片加进另一侧相册。
- 双端去重，最终按拍摄时间升序、最新在底部，沿用照片页查看、多选、状态与连续缩放。智能相关度只用于命中，不决定最终排序；服务器普通/智能两路分页、本机索引与合并排序要设计可证明的加载边界，不能仅取第一页声称是完整结果。分别处理无结果、权限不足、离线但本机有结果、智能不可用等状态。

## 7. 图库／集合页面

- 底部第四项改为**图库**。首页主分组：管理（收藏/归档/回收站）、发现（人物/地点/回忆）、分享整理（共享链接/标签/伙伴共享）；更多区域提供本机照片和服务器文件夹。账户与设置只从图库页进入。
- 内部开发版本所有入口可见，未完成者明确标“开发中／仅可查看”；公开首发时本清单承诺入口均须通过验收，不以占位页替代。服务器缺少能力/权限与客户端未实现分别说明。
- 收藏合并本机 PhotoKit 与服务器收藏，双端去重并区分单侧收藏状态；归档仅 Immich 资产。
- 回收站仅管理 Immich：查看、恢复、永久删除；不宣称能读取系统最近删除。人物可进入对应资产网格；地点地图/列表可进入对应照片；编辑人物与地点元数据不在本期。
- 回忆以卡片进入沉浸式故事浏览，无数据有空状态；共享链接可查看、创建、复制、撤销（仅服务器已有资产，额外选项依能力门控）；标签可浏览照片并对已有服务器照片赋予/移除；伙伴共享可浏览共享内容并按服务器权限邀请、撤销、调整权限。具体协议与服务端版本能力需实施前核验，不支持时不得呈现假按钮。
- 所有集合的照片操作遵守第 2 节统一身份、来源、删除、安全与状态合同。

## 8. 自动备份与核验

### 8.1 范围和调度

- 默认不上传；用户明确开启并手选设备相册，未选时无上传任务。照片页显示相册开关与备份相册选择独立；已选相册重叠的同一 PhotoKit 资产仅上传一次，不自动同步服务器相册结构。
- 默认仅 Wi-Fi，用户可分别允许蜂窝上传照片/视频；仅在允许的 Wi-Fi 条件下尝试获取 iCloud 原件，不可取得则待处理而非成功。iOS 后台调度不保证固定周期或持续执行，产品不得承诺实时备份。
- 取消相册选择立即重新计算范围，停止不再符合条件的待传任务；在传任务安全停止或完成后不再重试，已备份远端副本不自动删除。切换账户暂停旧账户隔离队列，切回并验证身份后恢复；移除账户彻底清理。

### 8.2 任务状态和正确性

- 持久化按账户+资产身份隔离的队列，流程：发现候选 → 原件获取与指纹 → 服务器查重 → 传输 → 服务器确认/关联 → 状态发布。查重确认已有有效 `assetId`，或上传成功并获得有效 ID，才显示“已备份”。请求失败、无结果、原件不可读均为待处理/未知/失败，不冒充未备份。
- 临时错误退避自动重试；不可恢复错误展示原因，可由备份面板查看并重试。面板至少展示已确认、待处理、上传中、等待 Wi-Fi/iCloud 原件、失败的数量与单项详情；有暂停/恢复控制，不提供照片页手动上传。
- 用户仅删云端而本机仍在已选备份相册时，**下一轮自动重传**；删除前明确提醒。删除成功即清理旧服务器关联并重新排队/核验，不能用旧缓存继续显示成功。
- `NativeCloudStatus.swift` 的原件核验与持久化可复用，但应拆分查重与上传职责；取消普通用户“清除匹配缓存并重新比对”入口。只有主动移除相应账户时清理该账户指纹/映射；系统级彻底退出所有账户时按同一规则逐账户清理。

## 9. 设置、账户与权限

- 仅从图库页进入设置。首期邮箱密码及 API Key 登录；支持多服务器/多账户列表，用户可切换，OAuth/SSO 非本期。账户缓存、匹配、原件指纹、上传任务、缩略图和错误状态按服务器身份+用户身份隔离。
- **切换**：停止旧传输，保留其隔离队列，切回验证身份后才恢复；新账户加载期间可先显示本机照片，云状态为未知，不借用旧账户数据。
- **退出登录**：结束当前会话并清除有效凭据，保留非敏感账户配置与隔离的非凭据队列以供再登录验证后恢复；**移除账户**：确认后删除该账户凭据、队列、指纹/匹配及私密媒体缓存，不删除系统或服务器照片。实现时区分退出与切换，绝不因旧 Flutter 凭据残留自动重新登录。
- 连接默认系统信任的 HTTPS；HTTP 仅在确认为私有网络地址并由用户明确许可时受限启用，不静默传输凭据。自签 HTTPS 使用**逐服务器证书指纹固定信任**，展示指纹、首次确认、证书变化停止请求并要求重新确认；认证、缩略图、视频、上传和发现流程共用信任策略，不提供“忽略证书错误”。代理或重定向不得泄漏认证头。具体 ATS/证书信任实现与 Apple 审核要求在开发时核实。
- 照片权限拒绝时云端照常使用；有限授权只展示/搜索/备份获授权资产，提供增补授权和系统设置入口。清理缓存只清缩略图、预览与临时分享文件，不清匹配/指纹/队列。诊断可显示版本、连接、队列统计及错误码；导出时移除凭据、照片内容和私有路径。

## 10. 实施顺序、依赖与完成定义

按用户选择优先**逐页面覆盖**，但每页功能必须复用第 2 节最低安全合同。建议用以下可独立验收的交付批次；不是工期承诺：

| 批次 | 目标交付 | 前置条件/退出条件 |
|---|---|---|
| 0 事实基线与安全底座 | 功能矩阵、目标服务器版本/API 校验、资产身份/状态/操作协议、账户隔离存储与测试夹具 | 证明不同账户不串照片、指纹/匹配/凭据/队列；核验不能被当作上传 |
| 1 照片页面覆盖 | 来源筛选、统一时间线、选择及完整批量目标操作；网格和位置优化可随后迭代 | 来源去重、危险删除范围、未知状态正确；页面主流程能用 |
| 2 查看器与详情覆盖 | 本机/双端收藏、原件分享、详情与失败重试，手势优先级 | 与照片页状态一致，视频/Live Photo 真机可用 |
| 3 相册覆盖 | 组合/来源筛选、成员增删、编辑、两种安全删除 | 不误删另一来源或把“移除成员”当成“删除原件” |
| 4 搜索覆盖 | 单框融合、本机有限搜索、筛选、分页与最近搜索 | 过期请求不覆盖结果；智能失败降级如实提示 |
| 5 图库集合覆盖 | 各已确认集合从首页到详情及承诺操作 | 无不可用的假按钮，服务端能力/权限可解释 |
| 6 自动备份覆盖 | 相册范围、持久化队列、查重、上传、确认、恢复与面板 | 可在断网、退出/切换、iCloud 原件未就绪时保持真实状态；仅删云端后符合规则自动重传 |
| 7 集中打磨与公开发布闸门 | 连续焦点缩放、滚动锚点、跨页一致性、大图库性能、无障碍、完整回归及发布准备 | 本次确认清单全数验收通过，公开版无“开发中”占位，正式发布流程另行达标 |

**注意：**备份后做不等于可以提前把仅查重称为“自动备份”。跨页状态/账户隔离要在第 0 批确立，之后在每个批次回归；第 7 批是集中调优而不是延迟修复危险操作。

### 统一验收矩阵（每项功能必须有记录）

- 状态：未做／开发中／代码完成／自动测试通过／真机验收通过；记录责任模块、目标 API、适用来源、错误与权限状态、证据链接。
- 自动化：资产去重与状态转换、跨账户隔离、分页/竞态、收藏双侧部分失败、成员操作范围、删除范围、队列恢复/幂等和旧数据迁移；补齐当前 `RunnerTests` 空示例。
- 真机：不同 iPhone/iPad 尺寸、横竖屏、动态字体/VoiceOver、有限/撤销照片权限、iCloud 原件、弱网/离线、大量资产、长视频、低内存、进程终止与后台恢复、服务器升级与账号切换。测试夹具不可包含真实用户照片或密钥。
- 一项只有 API 接口或页面入口不算完成；必须满足可到达、行为正确、权限/错误状态完整、可恢复、跨页一致及测试证据。

## 11. 待实施时验证的技术边界（不擅自改变已确认产品规则）

1. 锁定实际支持的 Immich 服务器稳定版本与 OpenAPI 契约，核对相册编辑、伙伴权限、共享链接、回收站、上传及媒体认证端点；按服务端版本/能力门控。
2. 核对 PhotoKit 收藏/相册成员变更权限、本机文件名可见性及本机自定义相册封面可行性；不支持时向用户反馈而非模拟系统写入。
3. 核对“全部/本机/云端”中已知匹配但服务器 DTO 未载入的投影与操作条件；跨页详情和筛选不得相互矛盾。
4. 混合搜索按时间排序与独立远端分页的完整性边界；结果总量、已加载范围和还有更多内容必须如实展示。
5. 账户切换期间 URLSession 后台任务的账号绑定、认证、撤销和恢复；自签证书固定信任须覆盖所有媒体与后台网络请求。
6. 上架前另设许可/品牌、隐私政策、权限用途、审核演示服务器、正式签名/TestFlight 与商店元数据检查；unsigned IPA 并非可上架构建。
